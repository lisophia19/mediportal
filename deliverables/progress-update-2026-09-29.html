Provider data expansion

The agent's routing knowledge now covers the full Orlin & Cohen group alongside Long Island Bone & Joint — 59 doctors across 14 offices, up from the original 10-doctor, 5-office baseline. Every one of those doctors' eligibility rules (which conditions they treat, age restrictions, and so on) is real data pulled from the practice's own provider spreadsheet, not invented. No routing logic had to change for this — the agent already resolves doctor/issue matching entirely from data tables, so adding more providers was a data change, not a rebuild.

Smarter triage & real preferences

Two meaningful upgrades to how the agent handles an unclear complaint or a caller's stated preference:
Triage now generalizes to any ambiguous pair, not just hip/spine. When a caller's complaint could plausibly be either of two conditions (hip vs. knee, neck vs. shoulder, a wrist fracture vs. wrist arthritis, and so on), the agent generates a real, specific discriminating question live for that exact pair — up to 3 rounds if needed — the same way a trained intake coordinator would ask, instead of a single hardcoded hip/spine script.
Location, doctor, and gender preferences are now honored end-to-end. A caller can say "I'd like whichever office is closest to Huntington" or name a specific doctor or a gender preference, and the agent actually applies that when finding and booking the appointment — not just acknowledging it and then booking the default option anyway.

Bugs fixed this week

All five below were caught on real test calls placed against the live number, not by reading code — and each is now covered by an automated regression test so it can't silently come back.
1. Returning patients are recognized instantly. A caller who opens with “I'm calling for a follow-up on my knee” used to sometimes get asked a clinical triage question meant only for new complaints. The agent now recognizes a follow-up caller immediately and skips straight to booking.
2. The pending-MRI check now reliably fires. Some visits require a patient to complete imaging first. That check was silently getting skipped for certain returning-patient phrasings. It now asks every time it should, and books an imaging appointment instead of the follow-up visit when the patient hasn't had it done yet.
3. Fixed a real call-stalling bug. A caller who named a specific office but not a specific doctor could cause the call to go silent partway through and never recover. Root-caused to how the underlying voice platform handles one specific kind of conditional response, and fixed by making that step fully deterministic instead of relying on the AI to decide whether to speak.
4. A rejected diagnosis no longer restarts the whole call. If a caller said "no, that's not quite it" to the agent's proposed diagnosis, the call used to discard everything and start over from "what can we help you with today?" — in one case this led to a caller with a genuine injury eventually being told the practice doesn't treat it. The agent now offers the other already-identified possibility first, the way a real front-desk person would.
5. Confirmation questions can no longer get silently skipped. Found on a real call: a yes/no confirmation question was never actually spoken out loud — the system answered on the caller's behalf and moved on. Added an explicit safeguard against this, and confirmed with a live test call that the confirmation is now genuinely asked every time.
Also shipped: a 10-second "please give us a moment" filler during any unusually long search, so the caller never sits in dead air; and a shortened, more natural doctor/location/gender preference question.

Verified with real test calls

We run an automated AI-to-AI test-calling setup that places real phone calls against the live number with a variety of caller personas, then reviews the actual outcome of every call. That's how these bugs were caught and confirmed fixed — not by guessing at edge cases, but by listening to what real calls actually did.
Two call recordings attached separately. One confirms the MRI-prerequisite flow (a returning patient is correctly asked about a pending MRI and booked into imaging). The other confirms the new generalized triage flow (a hip-vs-groin discriminating question is asked live and the caller's preferred office is honored in the booking).

In Progress

  • Slot-search dead ends. Found on a recent test call: when a caller asks for other times and none exist beyond what's already offered, the call currently ends instead of falling back to re-offering the times already on the table. Next in line to fix.
  • Routing to another department when we can't help. Designing how the agent hands a caller off to the right desk line (spine, pain management, etc.) when their issue can't be scheduled here, or when they ask to be transferred directly — using test numbers first so we can verify routing is correct before pointing at real department lines.
  • Insurance-aware prompting. Researching which plans (starting with Oscar and QualCare) require a referral or prior authorization before a visit, so the agent can ask the right follow-up question only when it's actually needed, not as a blanket extra step for every caller.
  • Provider coverage review. A few conditions currently map to specialists a patient would not expect — we would like to walk through those with the practice and correct the source data.
  • Call review dashboard. Every call is already captured with its transcript, routing decision and booking outcome. Next is richer review — filtering, match-quality flagging, and letting staff edit provider coverage directly instead of going through us.
  • Live schedule integration. Availability currently runs against a modelled calendar. Connecting the practice's real schedule is a configuration change, not a rebuild.
Not yet in scope: reschedule and cancellation by phone, multi-patient calls, and Spanish-language handling.
